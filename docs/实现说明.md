# 实现说明

## 背景

htop 的界面文字全部是 C 源码中的字符串常量，没有 gettext 或多语言资源机制
（上游需求 [htop-dev/htop#966](https://github.com/htop-dev/htop/issues/966) 仍为 open 状态）。
因此中文化只有一条路：改源码并重新编译。

难点不在翻译，而在**中文是双宽字符**：一个汉字在终端里占 2 列，但 htop 的所有
排版计算（功能键栏推进、仪表标题宽度、表格列宽、面板标题对齐）都基于 `strlen()` 的
字节数。直接把 `Mem` 换成 `内存`，整张表就会错位。

## 核心做法

新增 5 个函数（放在 `CRT.c` / `CRT.h`，不新增编译单元，避免改 automake）：

| 函数 | 作用 |
|---|---|
| `CRT_trans(en)` | 精确匹配查表翻译，未命中返回原文 |
| `CRT_transTrim(s)` | 忽略尾部空格查表，用于 `"Command "` 这类带填充的标题 |
| `CRT_transClip(s, n)` | 按终端列数裁剪，避免把 UTF-8 汉字截成半个 |
| `CRT_transPad(s, w)` | 译文补空格到指定列宽，用于定宽功能键标签 |
| `CRT_strWidth(s)` | `mbrtowc` + `wcwidth` 算终端列数 |

## 各文件改动

| 文件 | 改动 |
|---|---|
| `CRT.c` / `CRT.h` | 翻译表与上述工具函数；`CRT_i18nInit()` 读取 `HTOP_LANG`、`LC_ALL`、`LANG` |
| `CommandLine.c` | 在 `setlocale()` 之后调用 `CRT_i18nInit()` |
| `FunctionBar.c` | 功能键栏 x 推进、追加、点击命中都改用列宽；标签走 `CRT_transPad` |
| `Meter.c` | 仪表标题原固定 3 列，改为按译文宽度推进；四种渲染模式（文本/柱状/曲线/LED）都处理；仪表名与样式在列表中翻译 |
| `Row.c` | 列标题查表替换并保持原宽度；`RowField_keyAt()` 用列宽计算 |
| `TasksMeter.c` | `thr / kthr / running` 通过 `RichString_appendWide` 输出中文 |
| `MainPanel.c` / `IncSet.c` | 主功能键栏与搜索/筛选栏的中文标签数组 |
| `OptionItem.c` | 设置项（复选/数字/文本）在构造时翻译，一处覆盖全部选项 |
| `Panel.c` | `Panel_setHeader()` 统一翻译面板标题 |
| `CategoriesPanel.c` | 分类列表与仪表页列标题（`第1列`） |
| `DisplayOptionsPanel.c` | 顶部提示行改为先翻译再拼接 |
| `AvailableMetersPanel.c` | 可用仪表列表的名称、样式与回退逻辑 |
| `AvailableColumnsPanel.c` | 中文模式下只显示翻译后的列名，不再拼接英文描述 |
| `Action.c` | F1 帮助页整页翻译；`All users` 等对话框条目 |
| `Scheduling.c` | 调度策略与 fork 重置选项 |
| `TraceScreen.c` / `OpenFilesScreen.c` / `ProcessLocksScreen.c` | 信息页标题与提示 |
| `ScreenTabsPanel.c` | 默认屏幕标签名 |

## 翻译表结构

`CRT_zhTable[]` 是 `{ 英文, 中文 }` 的线性表，按功能分区：

- 进程列表列标题：**必须保持与原串完全相同的显示列数**，因此译文带手工补齐的空格，
  例如 `" VIRT "` → `" 虚拟 "`（1+4+1=6 列）
- 仪表标题、功能键标签：为定宽，译文短于原宽度时由 `CRT_transPad()` 补空格
- 帮助页、对话框：整句翻译，靠 `wcwidth` 保证输出不越界

## 验证方法

在 tmux 里以 120×30、120×34 等尺寸运行，`tmux capture-pane -p` 抓屏后
按单元格（CJK 记 2 列）展开，对比中英文表头各列起止位置是否一致。
